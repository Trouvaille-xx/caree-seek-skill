# 创始人 / 管理层背调规范（background check）

数据源仅限**公开 Web 信息**（新闻、公司官网、公开融资报道、公开个人主页）。
不使用登录墙或付费数据源，不采集个人隐私。所有结论标注来源与日期。

## 1. 背调对象选择

按 `config.json` 的 `bg_scope`：

- `top_n`（默认）：取岗位数最多的前 N 家公司（`top_n`，默认 5）。
- `shallow_all`：对所有出现过的公司各做 1 次轻量搜索，只填一句话摘要。
- `manual`：先向用户确认公司清单，再执行。

## 2. 搜索查询模板（每家公司 ≤5 条）

按顺序执行，命中即可停止：

1. `"{公司名}" 创始人 背景`
2. `"{公司名}" 融资 最新 轮次`
3. `"{公司名}" 裁员 欠薪 或 拖欠`
4. `"{公司名}" 诉讼 被执行 或 经营异常`
5. `"{公司名}" 官网 招聘`（确认主体与业务）

技巧：
- 搜索词必须带公司全名；如果有同名公司，追加「+ 行业」或「+ 城市」。
- 优先取公司官网、权威媒体、公开工商摘要；论坛爆料只作为「待核实」风险信号。
- 注意搜索结果日期，优先近 18 个月信息。
- 不收集个人联系方式、家庭信息、私人社交账号。

## 3. 同名消歧（硬规则）

只有在满足以下 **≥2 个信号** 时才把信息挂到该公司名下：

- 与岗位所在城市一致；
- 与岗位行业一致；
- 官网/招聘页与采集到的岗位/JD 有业务重合；
- 公开报道中出现与公司业务一致的产品/品牌。

不满足 → `confidence=low`，并在 `disambiguation_note` 写明「名称可能对应多个主体，未完全确认」。

## 4. 置信度分级

| 等级 | 条件 |
|---|---|
| high | 公司官网或 ≥2 个独立可信来源相互印证 |
| med | 1 个可信来源（权威媒体/公开工商摘要） |
| low | 仅论坛/聚合站摘要，或存在同名歧义 |

每条 `sources` 必须带 `{title, url, date}`；没有来源的结论不要写。

## 4.1 老板 / 团队背景评分（team_score）

`analyze.py` 把 `founder.name`、`founder.background`、`extras.联合创始人 / 创始人背景 / 法定代表人` 拼成履历文本，做规则评分（0–100）：

| 信号 | 加分 | 上限 |
|---|---|---|
| 基础分（有履历） | +44 | — |
| 名企 / 大厂 / 头部机构出身 | 每项 +10 | +30 |
| 顶级高校（清北复交、常春藤、QS 前列等） | 每项 +12 | +24 |
| 创始人 / CEO / CTO / 副总裁 / 合伙人等角色 | 每项 +6 | +18 |
| 硕博 / MBA / 海归 / 连续创业 / 上市或 500 强 | 每项 +5 | +15 |
| 知名企业家共事 / 投资（雷军、马云等） | 每项 +6 | +12 |
| 背调置信度 | high +10 / med +5 | — |

等级：**≥80 强 / ≥60 较好 / ≥45 一般 / <45 有限**；无履历 = **未评估**。
报告卡片与 Excel 同时输出「评分等级 + 评分依据（signals）」。
这是关键词线索，不是能力评价；同名消歧未完成时置信度低，不能单独作为决策依据。

## 5. 风险信号分类（只写“待核实”线索）

- `经营风险`：持续亏损、业务收缩、经营异常
- `用工风险`：欠薪、拖欠社保、裁员传闻
- `法律风险`：诉讼、被执行、失信
- `融资风险`：融资失败、估值下调、投资人退出
- `口碑风险`：公开平台大量负面评价（引用来源，标注未核实）

表述规范：写「2025 年裁员传闻（来源：X，待核实）」，不要写「该公司正在裁员」这类断言。

## 6. 公司与创始人字段（profile JSON）

```json
{
  "display_name": "某公司",
  "company_key": "自动生成，勿手改",
  "aliases": ["旧名/英文名"],
  "tier": "tier1|tier2|tier3|unknown",
  "funding_stage": "天使轮/A轮/.../已上市/未上市",
  "size": "100-499人",
  "industry": "企业服务",
  "founded": "2019",
  "founder": {
    "name": "可选",
    "background": "一句话履历，注明来源",
    "confidence": "high|med|low"
  },
  "recent_news": [{"headline": "...", "date": "2026-09-01", "url": "https://..."}],
  "risk_signals": ["欠薪爆料（来源：论坛，待核实）"],
  "sources": [{"title": "官网", "url": "https://...", "date": "2026-10-01"}],
  "confidence": "high|med|low",
  "disambiguation_note": "",
  "fetched_at": "2026-11-08T12:00:00+08:00"
}
```

> 报告、Excel 与匹配报告会展示 `team_score`（由 `analyze.py` 计算），以及 tier / 融资 / 规模 / 行业 / 新闻 / 风险 / 来源 / 消歧说明；
> `founder` 字段保留原始履历，`team_score` 不写回 profile，避免把派生分数当原始事实。

## 7. 执行与入库

1. 用宿主 agent 的 Web 搜索工具逐家搜索（agent 无关：WebSearch / 其他 harness 的搜索能力均可）。
2. 如实记录来源；没有把握就标 low 并写消歧说明。
3. 每完成 2–3 家入库一次，便于断点续跑：

```bash
python scripts/ingest.py --run <run> --kind profile --file profiles-batch.json
```

4. 入库后 `state.profiles_done` 会记录已背调公司；重复入库会覆盖同名文件（幂等）。
5. 背调结束后再运行 `analyze.py` 与 `report.py`，报告中会出现背调卡片与风险徽章。

## 8. 边界

- 只做「辅助判断」，不做事实认定；报告固定附带合规声明。
- 不评价个人私生活；不采集敏感个人信息。
- 所有风险信号必须保留「待核实」字样与来源链接。
